# ROX P0 B1–B3 evidence — 2026-09-20

Scope: resource-scoped Shopify inventory writes, retirement of historical
merchant-wide capacity claims, and resource-resolution reads. All observations
below are synthetic/local; they are not presented as live-production results.

## Migration 021 fixture

A disposable PostgreSQL database was migrated through `021`, then given one
synthetic historical active Shopify claim with field `capacity_per_day`. The
idempotent migration body was replayed to verify the data transition.

| Measure                            | Before | After |
| ---------------------------------- | -----: | ----: |
| Active unscoped fixture claims     |      1 |     0 |
| Superseded unscoped fixture claims |      0 |     1 |
| Per-merchant audit events          |      0 |     1 |

The retained claim had `resolution_status = 'superseded'` and
`resolution_note = 'Migration 021: retired unscoped capacity claim; use
resource.<resourceId>.(inventory|capacity)'`. The event reason was
`retired_unscoped_capacity_claim`. A demo reset plus full merchant
re-resolution left the fixture `superseded`; operational claim readers exclude
rows carrying this permanent retirement note while history readers retain them.

## Integration verification

- Exact-location inventory: two Shopify inventory items for the same merchant
  produced two independently resolved fields,
  `resource.<id>:1.inventory` and `resource.<id>:2.inventory`.
- Conflict isolation: conflicting observations for item 2 changed only its
  field to `conflicted`; item 1 remained resolved and its last known-good value
  remained available.
- Candidate read: a binding whose resource field was conflicted returned no
  candidate and included the exact reason
  `resource.<resourceId>.<inventory|capacity>:conflicted`.
- Broad catalog regression: 100 synthetic recipe cases passed before the new
  focused conflict case; the focused resource-conflict case also passed.

Commands used the repository's installed TypeScript compiler and Vitest
runners against disposable database `molecule_b123_20260920`. Live before/after
counts must be captured separately when migration 021 is deployed; this file
does not infer them from synthetic data.
